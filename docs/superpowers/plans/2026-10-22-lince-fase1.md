# Lince Fase 1 (núcleo + CLI) — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CLI `lince` que indexa volúmenes NTFS leyendo la MFT (o recorre carpetas como respaldo) y busca por nombre en milisegundos.

**Architecture:** Workspace Rust con tres crates: `lince-ntfs` (parser NTFS puro sobre bytes + lector de MFT genérico sobre `ReadAt`), `lince-core` (índice compacto, consultas, búsqueda paralela, recorrido de carpetas, apertura de volúmenes en Windows) y `lince` (binario CLI). El parser es independiente de Windows, así que se prueba en Linux con imágenes NTFS reales.

**Tech Stack:** Rust estable, `rayon`, `memchr`, `regex`, `chrono`, `clap`, `windows-sys` (solo Windows), `flate2` (pruebas).

**Spec:** `docs/superpowers/specs/2026-10-22-lince-design.md`

## Global Constraints

- Identificadores en inglés; comentarios, mensajes y documentación en español.
- Sin `unsafe` salvo en la capa Windows (FFI) y el buffer alineado, con comentario `// SAFETY:`.
- Lecturas del volumen alineadas a 4096 bytes (requisito de los *handles* de volumen).
- Profundidad de lectura: NVMe 32 hilos × 4 MiB, SSD 8 × 2 MiB, HDD 2 × 1 MiB, desconocido 4 × 2 MiB.
- No copiar código de UFFS ni de proyectos CC BY-NC.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` y `cargo test` limpios.

## Review Focus

1. Registro con *fixup* inválido o corrupto → se descarta ese registro y se cuenta; nunca *panic*.
2. Archivo con muchos hard links → lista de atributos y registros de extensión; todos los nombres deben aparecer.
3. MFT fragmentada → se leen todos los fragmentos en el orden correcto de FRS.
4. Nombres Unicode y mayúsculas (`Canción.TXT` encontrado con `canción`) .
5. Carpetas sin permiso en el recorrido → se omiten, se cuentan y el resto sigue.

### Task 1: Fixtures NTFS reales

**Files:** Create `lince/tools/gen-fixtures.sh`, `lince/fixtures/{basico,muchos}.img.gz`, `lince/fixtures/{basico,muchos}.expected.tsv`

- Script (root + FUSE): `mkntfs` + `ntfs-3g`, crea árbol con Unicode, nombres largos, vacíos, residentes, grandes, hard links (300 en `muchos` → lista de atributos), ADS, borrados, anidación profunda, MFT fragmentada (intercalar archivos grandes con creaciones). Escribe `ruta_relativa\ttamaño\tD|F` ordenado.
- Verificación: script termina con exit 0 y los `.gz` pesan < 2 MB en total.

### Task 2: `lince-ntfs` — boot, data runs, fixups, registros

**Interfaces (produce):**
- `parse_boot_sector(buf: &[u8]) -> Result<BootSector, NtfsError>`; `BootSector { bytes_per_sector: u32, bytes_per_cluster: u32, mft_lcn: u64, record_size: u32 }`
- `decode_runs(bytes: &[u8]) -> Result<Vec<DataRun>, NtfsError>`; `DataRun { lcn: Option<u64>, clusters: u64 }`
- `apply_fixups(rec: &mut [u8]) -> Result<(), NtfsError>`
- `parse_record(frs: u64, rec: &[u8], keep_runs: bool) -> Result<Option<ParsedRecord>, NtfsError>` (`None` = sin firma o no en uso)
- `ParsedRecord { frs, sequence, base_frs: Option<u64>, is_dir, std_info: Option<StdInfo>, names: Vec<FileName>, data_size: Option<u64>, nonresident: Vec<NonResidentAttr>, attr_list: Option<AttrList> }`

Pruebas (unitarias con registros sintéticos): boot 4 KiB/512 B; runs con LCN negativo relativo y *sparse*; fixup correcto y fixup corrupto → `Err`; nombre DOS excluido; tamaño solo del segmento VCN 0.

### Task 3: `lince-ntfs` — lector de MFT

**Interfaces (produce):**
- `trait ReadAt: Sync { fn read_at(&self, offset: u64, buf: &mut [u8]) -> io::Result<()> }` (implementado para `std::fs::File`)
- `read_layout(vol: &impl ReadAt) -> Result<MftLayout, NtfsError>`; `MftLayout { boot, extents: Vec<Extent>, record_count: u64, bitmap: Vec<u8> }`
- `read_records(vol, &layout, &ReadOptions{threads, chunk_bytes}) -> Result<MftScan, NtfsError>`; `MftScan { records: Vec<ParsedRecord>, bad_records: u64, bytes_read: u64 }`

Pruebas (`tests/imagen.rs` con fixtures): `muchos` tiene `extents.len() > 1`; los registros leídos con 1 hilo y con 8 hilos son idénticos; los registros fuera del *bitmap* no se leen (`bytes_read` < tamaño de la MFT).

### Task 4: `lince-core` — índice desde la MFT

**Interfaces (produce):**
- `Index` con `len()`, `entry(i) -> &Entry`, `name(i) -> &str`, `path(i) -> String`, `is_dir(i)`
- `Entry { parent: u32, name_off: u32, name_len: u16, flags: u16, size: u64, modified: u64, created: u64 }` (tiempos FILETIME)
- `index_from_mft(label: &str, scan: MftScan) -> Index` (excluye metadatos `$` FRS 0–15 salvo la raíz 5 y el árbol `$Extend`)

Pruebas: para cada fixture, el conjunto `(ruta, tamaño, D|F)` del índice es **igual** al `.expected.tsv`.

### Task 5: `lince-core` — consultas y búsqueda

**Interfaces (produce):**
- `parse_query(s: &str) -> Result<Query, QueryError>`; sintaxis de la spec (`ext:pdf;docx`, `size:>10mb`, `size:1kb..2mb`, `dm:2026-10`, `dm:>=2026-01-01`, `file:`, `folder:`, `path:texto`, `regex:expr`, frases entre comillas, comodines).
- `search(index: &Index, q: &Query) -> Vec<u32>` (paralela, excluye la raíz)
- `sort_results(index, &mut [u32], SortKey, desc: bool)`; `SortKey { Name, Path, Size, Modified }`

Pruebas: sin distinguir mayúsculas con Unicode; AND de términos; `*.txt` ancla al nombre completo; rangos de tamaño y fecha (hora local); consulta vacía devuelve todo; error claro ante `size:>abc`.

### Task 6: `lince-core` — recorrido de carpetas

**Interfaces:** `walk(root: &Path) -> io::Result<(Index, WalkStats)>`; `WalkStats { dirs, files, errors }`. Paralelo con `rayon`; no sigue symlinks/junctions.

Pruebas: árbol temporal → mismo conjunto `(ruta, tamaño)` que el creado; carpeta sin permiso (Unix `chmod 000`) cuenta 1 error y el resto aparece.

### Task 7: Capa Windows + CLI + CI

**Files:** `lince-core/src/windows.rs` (volúmenes NTFS, apertura `\\.\C:` alineada, tipo de disco), `lince/src/main.rs`, `.github/workflows/lince.yml`

- CLI: `lince [--volume C:]... [--path DIR] [--image ARCHIVO] [--limit N] [--sort name|path|size|date] [--desc] [--csv ARCHIVO] [--stats] [CONSULTA...]`. Sin permisos → aviso en español y recorrido de la raíz del volumen.
- Prueba CLI (Linux): `--image fixtures/basico` encuentra `Canción ñ.txt`; `--csv` escribe cabecera `ruta;tamaño;modificado`.
- CI Windows (administrador): crea árbol de prueba en el volumen de `RUNNER_TEMP`, ejecuta `lince --volume X: --stats marcador-lince` y compara rutas y tamaños; sube `lince.exe` como artefacto. CI Linux: fmt, clippy, tests.
